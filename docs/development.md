## Set up the checkout

Install Node.js 24+ and PostgreSQL 18+ tools, then install locked dependencies:

```sh
npm ci
```

`npm run dev` and `npm start` run `node src/server.js`. The server serves browser
modules from `public/` and allowlisted dependencies through its local import map.
Runtime startup needs no frontend build. The language Worker uses a checked-in
bundle generated by the development toolchain.

## Repository map

| Path | Responsibility |
| --- | --- |
| `src/server.js` | HTTP routes, authentication, project operations and compiler orchestration. |
| `src/database.js`, `db/schema.sql`, `db/migrations/` | Database initialization, compatibility checks and migrations. |
| `src/project-*.js`, `src/versions.js`, `src/builds.js` | Storage, identity, authorization, compensation, history and builds. |
| `src/collab.js` | Server-authoritative text collaboration. |
| `src/pipeline/` | Lua graphs, approvals, native execution, layout, composition and run authority. |
| `src/compile-diagnostics.js`, `src/source-mapping*.js`, `src/lilypond/` | Diagnostics and native PDF/source adapters. |
| `src/admin.js`, `src/audit.js`, `src/retention.js` | Accounts, audit records and retention. |
| `src/request-security.js`, `src/throttle.js`, `src/lifecycle.js` | Request admission, work limits and shutdown. |
| `public/Iris.html`, `public/iris.css`, `public/iris-*.js` | Shipped UI and editor, preview and administration controllers. |
| `public/languages/`, `public/vendor/language-worker/` | Language-service source and generated Worker bundle. |
| `public/locales/`, `public/templates/` | Translations and initial template catalog. |
| `test/`, `scripts/` | Tests, disposable runners, screenshots and source packaging. |
| `docs/`, `branding/` | Published guides, screenshots and product artwork. |

Keep runtime data outside source inputs. `DATA_DIR` defaults to ignored `./data`;
verification scripts create separate temporary storage.

## Build editor-language sources

Read [Editor language support](editor-languages.md) before changing the language
service. Edit the grammar, tokenizer, catalog or query source under
`public/languages/latex/` or `public/languages/lilypond/`. Regenerate parsers with:

```sh
npm run build:languages
npm run check:languages
```

The generator writes `parser.mjs` and `parser.terms.mjs`. Check mode compares
generated bytes without writing. Do not edit generated parsers by hand.

After grammar, tokenizer, recovery, pure-factory or Worker-protocol changes,
regenerate the language Worker too:

```sh
npm run build:language-worker
npm run check:language-worker
```

The locked esbuild toolchain generates `public/vendor/language-worker/worker.mjs`
and its version module. Module Workers do not inherit the page's import map.
Commit generated files with their source changes so production-only installs can
use them without a build toolchain.

Add syntax examples and UTF-16 annotations to
[`test/fixtures/languages/cases.json`](../test/fixtures/languages/cases.json).
Follow the [fixture guide](../test/fixtures/languages/README.md) for source
provenance, roles and caret contexts. Cover incomplete input, comments/literals,
incremental changes and the mounted editor interactions affected by the change.

## Run the tests

Use an unprivileged POSIX account with PostgreSQL 18+ tools on the host:

```sh
npm test
```

`npm test` calls `node scripts/test.cjs`. The runner creates a loopback-only
PostgreSQL cluster, generated credentials and isolated HOME/TMPDIR/storage. It
ignores the checkout's `.env` and inherited database credentials, and removes its
owned resources after completion or interruption. Do not use an existing Iris
database for tests.

Select files, filter names or adjust the runner's options:

```sh
node scripts/test.cjs test/project-deletion.test.js test/retention.test.js
node scripts/test.cjs --pattern 'crowded tabs' --browser test/ui-visibility.browser.test.js
node scripts/test.cjs --help
```

| Option | Purpose |
| --- | --- |
| `--browser` | Enable browser tests with installed Chrome. |
| `--browser-executable PATH` | Use a particular Chromium executable. |
| `--native` | Enable real compiler tests. |
| `--lua` | Enable tests using installed Lua 5.4/5.5. |
| `--pg-bin DIR` | Select PostgreSQL tools instead of `pg_config --bindir`. |
| `--pattern REGEXP` | Filter test names. |
| `--concurrency N` | Set test-file concurrency. |
| `--timeout MS` | Set the whole-suite deadline. |
| `--test-timeout MS` | Set the per-test deadline. |
| File paths | Run selected top-level files; omission selects `test/*.test.js`. |

Use `node --test` for pure modules. Database tests should use the disposable
runner; a direct run requires an isolated `TEST_DATABASE_URL` and the permissions
needed by its fixtures.

### Browser and native gates

Playwright Core uses an installed browser; `npm ci` does not download one.
Native navigation tests need `pdflatex`, `synctex`, LilyPond 2.26 and `gs`.
Install the other TeX engines and bibliography tools for tests that invoke them.
Use Lua 5.4/5.5 for pipeline tests.

```sh
node scripts/test.cjs --browser --native --lua --timeout 1800000
```

For a focused run:

```sh
node scripts/test.cjs --browser test/pipeline.browser.test.js --lua
node scripts/test.cjs --native test/source-mapping.native.test.js
node scripts/test.cjs --browser test/source-navigation.browser.test.js
```

`npm run test:integration`, `npm run test:browser` and `npm run test:native`
provide selected entrypoints. Enable the tools needed by the behavior you change;
missing required tools fail an enabled test. Read skip messages when reviewing
a run.

Capture and smoke scripts share `withBrowser` in `scripts/lib/browser.cjs`.
On POSIX, `browserTemp(work, env)` gives Chromium an owned short `/tmp/iris-b-*`
socket path. Register cleanup before launch and remove it only after confirmed
browser closure. Keep Playwright profiles inside the disposable workspace.
Other child processes use the workspace's ordinary temporary directory.

## Installation smokes

Exercise native installation, compilation, navigation, Lua execution, restart
and separate-instance restore with:

```sh
node scripts/smoke.cjs --native --browser
```

This requires the native/browser prerequisites above. Omit `--browser` to run
HTTP checks without browser painting.

For a running Docker or Podman engine:

```sh
node scripts/smoke.cjs --engine docker
node scripts/smoke.cjs --engine podman
node scripts/smoke.cjs --help
```

Select a Podman connection and Compose provider when needed:

```sh
node scripts/smoke.cjs --engine podman \
  --connection "$PODMAN_CONNECTION" \
  --compose-provider "$PODMAN_COMPOSE_PROVIDER"
```

The source directory must be visible to the engine for Compose's init-script
mount. The script uses your selected engine; it does not provision a VM or daemon.
Container smoke builds the local Iris image and uses separate source/restore
volumes. The stock image reports missing compilers until a toolchain is installed.

Smoke refuses to overwrite an existing Iris image. Use `--use-image` to use and
retain that image. The runner removes its own projects, containers, processes and
storage. If cleanup fails, use the reported resource names to inspect and remove
those resources.

## Source packaging

Package a reviewed Git revision into a new output directory:

```sh
node scripts/release.cjs --ref HEAD --output .drafts/source-package
```

The script creates a version-named source archive and `SHA256SUMS` from immutable
Git objects. Working-tree changes do not enter ref-based packaging. It does not
create a tag or modify the index.

For a candidate without a commit, provide a JSON array of source paths:

```sh
node scripts/release.cjs --candidate "$SOURCE" \
  --manifest "$MANIFEST" --output "$NEW_OUTPUT_DIRECTORY"
```

Review the manifest. Candidate mode includes exactly the named permitted files,
including new files, and works without Git. Both modes validate required inputs,
package/lock agreement and paths; they exclude secrets, runtime data, dependencies
and internal working records. `.env.example` is an intended input.

The packager sorts paths and normalizes archive metadata. Its limits are 20,000
entries, 64 MiB per file and 512 MiB total source, subject to ustar path limits.
Review `scripts/release.cjs:included()` when adding a source or asset format.
Extract the archive into a new directory, install locked dependencies and run
the relevant tests and smoke commands there.

## Persistence contract

`src/database.js` owns schema initialization, compatibility checks and supported
migrations under one transaction and advisory lock. `db/schema.sql` describes
the current schema; `db/migrations/` contains upgrade steps. Update these together
when changing persistence. Unsupported or malformed schema state fails without
modification. See the operator [upgrade procedure](administration.md#upgrade-iris).

Current source, assets and fonts live under `DATA_DIR/projects/<lowercase UUID>`.
`.iris/project.json` stores tree/settings without duplicating source text.
Published builds use `output/<build-id>/`; templates use the separate mutable
catalog. PostgreSQL stores relational records and text revision history.

Use `src/ids.js` for persistent UUIDv7 identities. Generate IDs before database
insertion when filesystem paths need them. Use random bytes for secrets.
`audit_events.id` uses a BIGINT identity.

`project_files` owns file identity across rename/move and soft deletion.
Creation, import and save reconcile client/source-tree IDs into that ledger.
Imports allocate new identities and grant no Lua execution approval.

Whole-project saves require `baseRevision`. Missing or malformed preconditions
return `428 PROJECT_REVISION_REQUIRED`; stale revisions return
`409 PROJECT_REVISION_CONFLICT` before mutation. Accepted saves advance revision.
Realtime flushes and checkpoints do not. Pipeline snapshots flush live room text
under the project gate; run creation records compilation checkpoints. The UI
saves through its mutation queue before requesting a run.

The per-project gate coordinates database transactions and filesystem
compensation. Strict reads fail rather than substituting empty source. Uncertain
commits or failed compensation retain recovery bytes and block access. Project
deletion uses durable receipts and removes data only after confirmed commit.
Follow [recovery states](administration.md#recovery-states).

Text history stores changed lossless UTF-8 source up to 16 MiB. Compilation,
snapshots, idle editing, deletion and restore can create revisions. Restore first
records changed current text, then adds the restored version. File identities and
readable author labels survive rename and account deletion.

## Collaboration contract

`/api/collab` uses authenticated WebSockets and CodeMirror operational
transformation. The server owns document text and ordered versions. Stale clients
pull updates, rebase pending edits and retry. Obsolete sockets or file openings
cannot replace the current session. New files join after receiving canonical IDs.

Use live room text for saves, checkpoints and builds. Deletion closes the room;
rename preserves its stream. Permission changes recheck access and can make an
editor read-only or close membership access. Run one Iris process per
database/storage installation; the room state and gates are process-local.

The browser waits for its pending edits to return through the ordered update
stream before submitting source-dependent HTTP mutations or replacing the active
document. A push acknowledgement alone does not confirm the text. The wait drains
later local edits too, retains the typing debounce outside explicit actions, and
fails after ten seconds without confirmation. Cancellation, identity replacement
and permission loss cannot acknowledge pending work.

Each `opened` frame includes an ephemeral `streamId` for the room lifetime.
Reconnect can pull and rebase unconfirmed edits against that same stream. A new
stream or full resync cannot replace a pending local buffer: the browser retains
it for copying, blocks further writes and requires explicit discard/reopen for
recovery. Text entered before the initial room response receives the same
protection. Older clients can ignore the additive field; a client with no retained
stream identity refuses to replay pending edits after reconnect.

Presence is ephemeral and scoped to readable projects/files. Positions follow
text updates. Structure-based overlap notices advise collaborators without
locking the source. Build notices identify completed output; clients retrieve it
through authorized HTTP routes.

Pipeline notices carry project/target identity, accepted request order and event
sequence. Compare ordering values numerically. Fetch authorized details and
resynchronize after the server confirms a project watch on reconnect. Older
responses cannot replace newer state or another project/target selection.

## Compiler contract

`projectType` selects LaTeX or LilyPond; omission selects LaTeX. Ordinary
compilation saves source and copies byte-exact input under the project gate into
`DATA_DIR/.build-staging/`. Compilers run outside the gate. Successful publication
renames complete output to immutable `output/<build-id>/`. Failed builds retain
diagnostics and publish no partial artifacts.

LaTeX tools are `pdflatex`, `xelatex`, `lualatex`, `xetex`, `bibtex`, `biber` and
`makeindex`. Custom profiles accept up to twelve ordered steps:

| Placeholder | Value |
| --- | --- |
| `[engine]` | Selected TeX engine. |
| `[main]` | Relative main source path. |
| `[jobname]` | Main filename without extension. |
| `[pdf]` | Expected PDF path under `output/`. |

TeX engine steps accept one relative source operand, `-synctex=<integer>`,
`-recorder`, `-draftmode` and `-8bit`. Managed arguments may repeat only their
exact values: `-interaction=nonstopmode`, `-halt-on-error`, `-file-line-error`,
`-no-shell-escape`, `-output-directory=output`. One- and two-dash forms work;
abbreviations, inline TeX, format selectors and extra source operands fail
validation. Mapping sets one managed `-synctex=1` or `-synctex=0`.

LilyPond uses a constrained `lilypond` step. Processes use argument arrays and a
reduced environment without backend credentials. XeLaTeX/LuaLaTeX receive
`OSFONTDIR` and a project-local `.iris/texmf-var` cache; Fontconfig refresh runs
when available. LilyPond receives the project root as `XDG_DATA_HOME` for fonts.
Follow the [native trust boundary](administration.md#compiler-trust-and-instance-boundaries).

Build responses include structured `diagnostics` and derived `warnings`/`errors`.
Stored empty diagnostic arrays are authoritative; readers do not reconstruct
warnings from trace text. Multipass selection uses the last complete successful
pass with the same engine/arguments, retaining auxiliary, failed-pass and
setup/publication diagnostics. A truncated pass cannot clear earlier warnings.
Logs obey `COMPILE_LOG_LIMIT`; ordinary diagnostics cap at 80 per severity.

Pipeline details read persisted step diagnostics with source/generated
provenance and the pipeline run budget. Identical messages from distinct steps
remain separate. Generated locations cannot attach to project files by filename.
Host failures retain stable codes in the terminal reason and, when space permits,
a structured diagnostic. The UI localizes host explanations, preserves authored
messages and retains a successful preview after failure.

Ordinary compilation checks pipeline enablement under the project gate and
rejects enabled projects with `PIPELINE_TARGET_REQUIRED`. For graph APIs and
artifact publication, see [Lua pipelines](lua-pipelines.md).

The artifact registry identifies previewable products. Build-file scanning also
exposes safe regular outputs such as MIDI and bibliography files. Symlinks,
special files and private navigation sidecars stay out of build downloads/ZIPs.
Project exports include ordinary filesystem output and retained sidecars, but
not database history or sharing memberships. Deleted files retain recorded
revisions, but file-history restore requires an existing project file.

## HTTP and session boundaries

Content routes recheck membership: nonmembers receive 404; members without a
required capability receive 403. Admin routes require current administrator
authority. Sessions carry `session_version`; password changes/resets, disablement
and local/SSO conversion invalidate earlier cookies. Role changes apply through
database authorization. WebSockets recheck on messages, heartbeats and expiry.

Unsafe methods and WebSocket upgrades require same-origin browser metadata.
A present Origin must contain one matching `scheme://authority`, with no path,
credentials, query or fragment. Duplicate, null and malformed values fail.
Without Origin, reject invalid/cross-site/same-site Fetch Metadata, then validate
a present Referer. `same-origin` metadata cannot override a foreign Referer.
With neither Origin nor Referer, `same-origin` metadata passes but `none` alone
does not. Native clients with all three absent still require authentication.

Unsafe API requests require `application/json`, optionally one UTF-8 charset.
A wrong type returns 415 even for an empty body. Missing type works only without
a transferred body; empty chunked requests still require it. Project ZIP import
permits raw ZIP. SSO callbacks use state validation. Maintenance and shutdown
refusals take precedence over request admission.

Consult route handlers and behavioral tests for request fields. The
[navigation API](source-navigation.md#http-api) owns its coordinates and limits.

## UI and documentation contributions

Use shared [color](ui-colors.md) and [size/spacing](ui-measurements.md) tokens.
Check mounted controls, keyboard access, focus, read-only behavior, both themes
and compact layouts. Follow [translation](../TRANSLATING.md) and
[template](../public/templates/README.md) conventions.

Write current behavior and task-based instructions. Keep measurements, testing
reports, historical implementation notes and proposals in Git-ignored working
records under `docs/superpowers/`. Preserve useful development material there
before removing it from a guide. See [repository documentation rules](https://github.com/GioMez/Iris/blob/feat/lua-plugins/AGENTS.md#documentation-ownership-and-cleanup).

Use the [screenshot capture](images/README.md#reproduce-the-captures) for real UI
images. Check local links, anchors, image paths, configuration names and commands
against the source. Exercise changed commands; do not add application tests that
only assert documentation wording.
